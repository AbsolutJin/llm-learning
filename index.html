How to use

  2. Read, then poke it. After each reading block there's a 🧪 lab on the two models you already run. Do it — an observed concept sticks far better than a read one.
  3. Aim for "I get it and I've seen it work," not 100% mastery per topic. You'll circle back.
  4. Tick the checkpoints — your progress saves in this browser automatically.
  5. You already know how to program, so Python is fast-tracked. The real time goes into the ML/LLM theory.

Phase A · Weeks 1–2

Python for developers

Become fluent enough in Python to read ML code and write your own scripts. You're not learning to program — you're learning Python's idioms and the "Pythonic" way of doing things you already know from JS/ABAP.

Concepts to nail

Python vs. JS syntax (indentation blocks, None/f-strings); data structures (list/dict/tuple/set); comprehensions; functions, *args/**kwargs, type hints; virtual environments & pip; the Pythonic mindset.

Resources

  • ⭐The official Python Tutorial — concise, aimed at people who already program. Skim Parts 3–9.
  • ⭐Real Python — best-in-class written tutorials. Start with "Python Virtual Environments: A Primer."
  • 📖"Effective Python" (Brett Slatkin) — 90 short "do it this way" idioms; read a handful per week.
  • 📖Automate the Boring Stuff — free; skim early chapters fast.
lab A — set up your Python workspace
  1. Check Python: python --version (install from python.org if missing; tick "Add to PATH").
  2. Make a project + virtual env:
mkdir E:\llm-lab; cd E:\llm-lab
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install requests openai

Write hello.py that prints 1–10 using a list comprehension. The point isn't the code — it's the workflow: venv → write → run.

Phase B · Weeks 3–4

ML & neural-net foundations

Understand the ground floor beneath LLMs: what machine learning is, what a neural network is, and what "training" does. Just enough to make the LLM material make sense — not a full ML degree.

Concepts to nail

What ML is (learn a function from examples, not hand-written rules); supervised vs. self-supervised (LLMs predict the next token); neural network = layers of weighted units, the "9B/27B" = billions of parameters; the training loop (predict → measure loss → nudge weights via gradient descent); inference (what your server does); the useful bit of math: vectors, matrices, "lots of matrix multiplication."

Resources

  • ⭐Google ML Crash Course — reading + interactive, developer-focused, minimal math. Your main Phase-B resource.
  • ⭐"Understanding Deep Learning" (Prince) — free, modern, readable book. Read Ch. 1–3 now; reference later.
  • 📖Nielsen — Neural Networks & Deep Learning — the patient classic. Ch. 1–2.
  • 🎥3Blue1Brown — Neural Networks — the one video worth it; unmatched visual intuition (~2 hrs).
lab B — see "inference" for what it is

With qwen running, open the web UI — you're watching inference: a trained network turning tokens into a next-token prediction, over and over. Ask it: "Explain gradient descent to a programmer in 4 sentences." Then judge the answer against what you just read. You're using the model and checking your own understanding.

Phase C · Weeks 5–8 · the core

How LLMs actually work

Four weeks, one theme each — tokens, attention, training & sampling, quantization. Every theme ends on your own machine.

Week 5

Tokens & embeddings

How text becomes numbers. Tokenization (text → token IDs; why "cat" is 1 token but "Qwen3.8" is several). Embeddings (each token → a vector capturing meaning; similar words → nearby vectors). Why token counts and context limits are everywhere.

  • ⭐Hugging Face LLM Course — reading, structured, practical. Your spine for Phase C.
  • ⭐Illustrated Word2Vec (Alammar) — the clearest visual-written intro to embeddings.
  • 📖Simon Willison on LLMs — grounded, practical writing.
lab — watch text become tokens (on YOUR server)

Your server exposes a tokenize endpoint. With qwen running:

curl -s http://127.0.0.1:8080/tokenize -H "Content-Type: application/json" -d "{\"content\":\"Hello, Qwen3.8! Grüße aus Deutschland 🚀\"}"

Watch the sentence split into token IDs. Try English vs. German umlauts vs. an emoji vs. a code snippet — see the count change. That is tokenization, live.

Week 6

The Transformer & attention

The architecture behind every modern LLM. Self-attention — for each token, the model weighs how relevant every other token is (Query/Key/Value). Positional encoding (how it knows word order). You want the intuition + the shape of the math, not to implement it.

  • ⭐The Illustrated Transformer — the most-recommended written explainer of attention. Read it twice.
  • ⭐Transformer Explainer (interactive) — click Embedding → Attention → FFN on a real GPT-2. Not a video.
  • 🖱️LLM Visualizer (Bycroft) — a 3D walk through every step of a small GPT.
  • 📖Lilian Weng — "Attention? Attention!" — deeper written treatment.
lab — feel attention via context

In the web UI, give a short story, then ask "who did X refer to?" Watch it resolve references across the text — that's attention weighting earlier tokens. Then paste a long document and ask about the first line: you're stressing the context window (Week 8).

Week 7

Training stages, inference & sampling

How a model becomes an assistant: pretraining (predict next token on the internet) → instruction-tuning → RLHF (why your instruct models are polite and follow directions). Then sampling: the model outputs a probability for every next token; temperature / top-p / top-k pick one — exactly the "Sampling & Penalties" tab in your UI.

  • ⭐Karpathy — "Intro to LLMs" (1 hr) — the clearest overview of pretraining → fine-tuning → RLHF.
  • 📖HF — "How to generate text" — written explanation of greedy/top-k/top-p/temperature with examples.
  • 📖Lilian Weng's blog — for depth when you want it.
lab ⭐ — become the sampler

In the Sampling & Penalties tab, take one prompt ("Write one sentence about the ocean"):

  • Temperature 0 → run 3×. Nearly identical (near-deterministic).
  • Temperature 1.4 → run 3×. Wild variety.
  • Play with top-p. Now the theory is something you did.
Week 8

Quantization, context & local inference

The practical layer you've already touched. Quantization (16-bit → 4/8-bit so a model fits your 8 GB VRAM — the Q4_K_M in your model names, and the size/quality tradeoff). KV cache (why long context costs memory; your --cache-type q8_0 halved it). GPU offload (-ngl, partial offload across GPU + RAM). Speculative decoding (your MTP flag).

  • 📖llama.cpp server docs — the reference for every flag you use.
  • 📖llama.cpp VRAM guide — practical, matches your hardware questions.
  • 📖KV-cache q8_0 deep-dive — now you have the theory to fully get it.
lab — measure the tradeoffs you now understand

Run qwen → option 1 (9B) and 2 (27B). Compare answer quality vs. speed (tokens/sec in the server log) vs. VRAM (nvidia-smi). You're measuring quantization, offload, and model-size tradeoffs — with the vocabulary to explain every number.

Phase D · Weeks 9–10

Working with LLMs in practice

Move from the web UI to code, and learn to steer models well.

Week 9

The API & structured output

The OpenAI-compatible chat API your server exposes (/v1/chat/completions): the messages array (system/user/assistant roles), streaming, params, and getting structured JSON you can use in code.

  • 📖OpenAI Chat Completions reference — your local server mimics this exact shape.
  • 📖openai-python — point it at http://127.0.0.1:8080/v1.
lab ⭐ — first code that talks to your model

In E:\llm-lab (venv active), create chat.py:

from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:8080/v1", api_key="not-needed")

resp = client.chat.completions.create(
    model="local",
    messages=[
        {"role": "system", "content": "You are a concise assistant."},
        {"role": "user", "content": "Give me 3 Python tips for a JS dev."},
    ],
    temperature=0.7,
)
print(resp.choices[0].message.content)

Run it with qwen live. This is the foundation of every LLM app. Then add stream=True; then ask for JSON output and parse it.

Week 10

Prompt engineering

System prompts, few-shot examples, chain-of-thought, specificity, evaluating outputs. The highest-leverage skill before you build anything.

  • ⭐Anthropic — Prompt Engineering — one of the best written, principle-based guides.
  • 📖promptingguide.ai — broad written reference (few-shot, CoT, etc.).
lab — measure a prompt's effect

Run a weak prompt ("summarize this") vs. a strong one (role + format + constraints + an example) on the same text via chat.py. Compare. Keep a personal prompts.md of patterns that work.

Phase E · Weeks 11–14 · the payoff

Building LLM-powered apps

Build real things. Your full-stack instincts take over here — the LLM is just a very capable, non-deterministic function you call.

Week 11

A real chat app

Wrap chat.py into something with memory (keep the messages array across turns) and a simple interface (CLI first; then a tiny web front end — your JS strength). Concept: conversation state is just resending the growing messages array each turn.

  • 📖Streamlit docs — fastest way to a Python UI, if you want one.
Week 12

RAG — Retrieval-Augmented Generation ⭐

The most important app pattern. To answer over your docs: (1) split into chunks, (2) embed them into vectors, (3) store them, (4) on a question, retrieve the most similar chunks and stuff them into the prompt. Demystifies the biggest buzzword in AI.

  • ⭐LlamaIndex "Learn" — built for exactly this.
  • 📖Embeddings: your server can produce them (/v1/embeddings with an embedding model), or use a small local embedder.
lab — RAG over your own docs

Build a script that answers questions about a folder of your own .md/.txt files. Start dead-simple — a few chunks, cosine similarity in NumPy — before reaching for a framework.

Week 13

Tool calling / function calling

Let the model call your functions (search, calculator, an API) by returning a structured request you execute, then feed the result back. The bridge from "chatbot" to "does things."

  • 📖Anthropic — Tool use — concepts transfer to local models.
lab — the model calls your function

Give your model a get_current_time() or a fake search() function and let it decide when to call it.

Week 14

Agents + capstone

An agent is a model in a loop — it plans, calls tools, observes results, and repeats until done. Know the idea and its limits (powerful, but they can loop/fail).

  • ⭐Weng — "LLM Powered Autonomous Agents" — the definitive written overview.
  • ⭐Anthropic — "Building Effective Agents" — when to use agents vs. simple chains.
  • 📖LangGraph — the 2026 standard for agent loops; skim after the raw concept.
capstone — ship one small thing

Pick ONE real project and build it end-to-end on your local models: a RAG assistant over your notes; an "explain this codebase" tool; a CLI agent using 1–2 tools. Ship it, then write down what surprised you.

Reference · Glossary

Token
A chunk of text (word/word-piece) the model reads and writes as a number.
Embedding
A vector of numbers representing meaning; similar meanings sit near each other.
Parameter / weight
One of the billions of learned numbers in the model (the "9B" / "27B").
Transformer
The neural-network architecture behind modern LLMs.
Attention
Mechanism letting each token weigh the relevance of every other token.
Pretraining
Learning language by predicting the next token over huge amounts of text.
Instruction-tuning
Further training so the model follows instructions / behaves as an assistant.
RLHF
Tuning with human preferences to make outputs helpful and safe.
Inference
Running the trained model to generate output — what your server does.
Temperature / top-p / top-k
Sampling knobs controlling the randomness of token choice.
Context window
How many tokens the model can attend to at once (your -c flag).
KV cache
Stored attention data for past tokens; grows with context (your --cache-type shrinks it).
Quantization
Storing weights at lower precision (e.g. 4-bit) to save memory (the Q4_K_M).
GPU offload (-ngl)
How many model layers run on the GPU vs. CPU/RAM.
RAG
Retrieval-Augmented Generation: fetch relevant text and add it to the prompt.
Tool / function calling
The model requests that your code run a function, then uses the result.
Agent
An LLM in a plan → act → observe loop using tools.

🔮 Future phase · not now

Training & fine-tuning your own models

Once Phase E is comfortable, the natural next frontier is making models your own. Don't start until the above feels solid — it's the most math- and compute-heavy layer. When you're ready:

  • •fast.ai — Practical Deep Learning for Coders — code-first path into training.
  • •Sebastian Raschka — "Build a Large Language Model (From Scratch)" (book) — implement a GPT yourself; the deepest understanding there is.
  • •Fine-tuning techniques — LoRA / QLoRA, and tools like Unsloth and HF transformers / peft.
  • •Andrew Ng — Machine Learning Specialization — if you want the rigorous from-scratch math.

You already have the hardware to experiment with small fine-tunes locally — a great motivator once you arrive here.
